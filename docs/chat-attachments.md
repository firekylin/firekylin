# 聊天图片与文本附件

聊天窗口可添加图片或文本文件、预览、移除并发送，也可只发送图片而不输入消息。图片与正文随私有会话保存，刷新、后续问答和失败重试都会重新发送实际内容，不会只把无法访问的 URL 交给模型。

## 支持范围

- 图片：静态 PNG、JPEG、WebP。每张最多 2 MiB、最长边 4096 像素；每条消息的图片最多 4 MiB，整个会话累计最多 12 张或 8 MiB，超限请新建对话。
- 文本：UTF-8 的 `.txt`、`.md`、`.markdown`、`.csv`、`.json`、`.log`。每个最多 32 KiB，每条消息合计最多 64 KiB。
- 图片和文本合计每条消息最多 5 个附件。空文件、无效 UTF-8、二进制文本、格式伪造、损坏图片、动图及超限文件明确报错，不静默截断或忽略。
- GIF、SVG、PDF、Office、压缩包暂不支持。部署平台或反向代理若有更低的请求体限制，需减少单次文件大小；图片经 base64 编码后体积约增大三分之一。

模型菜单中“可读图片”表示模型声明了独立的 `vision` 输入能力。`image` 仍只表示图片生成/编辑，不能据此上传图片进行问答。已包含图片的会话不能切换至不支持 `vision` 的模型，服务端也会在生成前重新校验，不会丢弃历史图片。

配套插件支持的模型：

| Provider | 可读图片的内置模型 | 协议 |
| --- | --- | --- |
| OpenAI | gpt-5.4、gpt-5-mini、gpt-5-nano、gpt-4.1 | Responses `input_image` data URL |
| Anthropic | claude-sonnet-4-6 | Messages base64 `image` block |
| Google Gemini | gemini-3-flash-preview | generateContent / streamGenerateContent `inlineData` |

自定义模型 ID、其他 9 个 provider、仅生成图片的模型暂不声明 `vision`。是否有账号访问权限、端点是否兼容以及上游模型是否仍可用，仍由服务商决定；本次没有真实服务商调用验证。

## 私密存储和校验

选择文件仅在浏览器本地读取和预览，发送时才随经过认证和 CSRF 校验的聊天 POST 上传。服务端先校验当前角色和会话所有权，再处理附件，不调用会生成公开附件文章的媒体上传接口、不创建公开链接，也不抓取外部图片 URL。

服务端使用 sharp 完整解码、校验图片魔数/声明 MIME、单帧、尺寸和字节上限，按原格式重新编码、校正方向并移除 EXIF/XMP/ICC 等元数据及尾部负载。数据库保存处理后的图片 base64、名称、尺寸与字节数；这不是加密存储，数据库和备份仍应按站点现有方式保护。图片和文本保存在消息 JSON payload，不新增文件系统或对象存储目录、不需要 schema 迁移；删除会话同时删除附件。聊天读取和 SSE 响应标记 `Cache-Control: no-store`。

模型实际接收 `messages[].images: [{mimeType, data}]`。适配器转换为服务商原生图片输入，保留其所属用户消息；图片不放进文本提示词，也不计入现有 400000 字符的文本上下文上限，而使用独立的图片数量/字节上限。AIClient 会重新校验能力和内容后才调用 provider。附件及识图结果仍是不可信数据，不提高工具权限、不跳过写操作确认。

包含附件历史的生成调用使用 `recordContent: false`。AI 日志不记录请求/响应正文或 HTTP 参数，防止图片和引用内容被复制进日志；保留身份、模型、状态和用量等元数据。AIClient 对原生图片输入也自动禁用审计正文。普通聊天的原有审计策略不变。插件及外部服务商仍收到实际内容，遵循各自的数据策略。

## 失败、升级与兼容

服务端开始 SSE 表示用户消息已保存，之后才清除待发附件；请求被拒绝时保留输入和附件。生成失败后，已保存图片可通过原有“重试回复”继续使用。网络结果不确定时应刷新记录核对，避免重复发送。切换会话清除未发送附件。

core 基于已合并的 #963，保持原有自定义流解析接口。配套插件图片适配分支基于已合并的 plugins#20，未改动协议解析器，普通文本、工具和图片生成路径保持兼容。先正式发布包含 `vision` 接口及 sharp 依赖的新 core，再发布对应插件；不能只合 core PR 而不发版。新版插件遇到旧 core 的图片请求会明确提示升级。部署时须安装 sharp 对应平台的运行时依赖。

聊天输入区使用 Ant Design X Sender：左下角附件入口，右下角模型选择、语音输入和发送/停止按钮；待发附件在输入框顶部预览并可移除。语音采用浏览器 SpeechRecognition，仅将识别结果加入草稿，需浏览器支持并允许麦克风权限；不支持或权限被拒绝时按钮禁用。
