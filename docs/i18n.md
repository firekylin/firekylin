# UI internationalization

The site-wide `locale` setting defaults to `zh-CN` and supports `en-US`. It changes UI text only; article bodies, titles, categories, navigation values and custom field values are not translated. The admin UI translates core page labels, validation, notifications, editor controls, and known API errors at render or action time.

## Translators

`t(key, vars)` returns plain text synchronously. Keys match exactly, including dots, colons and whitespace. Flat JSON dictionaries live in `locales/<locale>.json` inside the owning core, theme or plugin root. Only `{{name}}` placeholders are supported. Values are primitive strings, numbers, booleans or nullish values. Interpolation runs once; use the final consumer's escaping (React text or Eta `<%=`).

Fallback stays within the owner: exact locale, base language, default locale, original key. Empty translations are valid. Resources reject duplicate keys, inconsistent placeholders, prototype keys, oversized files and escaping symlinks.

Server factories accept the language directly: `coreTranslator('en-US')`, `themeTranslator(root, id, 'en-US')`, or `createTranslator({namespace, locale: 'en-US', resources})`. Requests store the language string in `ctx.state.locale`; no version or snapshot object is needed.

## Plugins

Use `ctx.t('保存')` in registration or callbacks. Each plugin retains its own dictionary even when invoked by another plugin or a theme. HTTP callbacks inherit the request's locale. For an independently scheduled task, explicitly call `ctx.withLocale(async () => { /* task */ })` at task entry to read the current persisted locale.

Strings evaluated during `register(ctx)` remain in that language until a safe plugin reload or worker restart. Changing locale does not rerun registration, restart workers or duplicate external side effects. Dynamic callbacks should call `ctx.t` when invoked rather than cache translated strings.

## Themes

Use `<%= t('阅读全文') %>` for escaped text. Every template receives `t` in its render scope through a fixed Eta header. Reserve this name for translation; do not redeclare it at template scope. Includes must preserve `firekylin.t` when passing explicit replacement data. Do not use raw output for translations.

The host translates only known display properties in `configElements` and `themeFields`. Names, defaults, submitted values and stored user configuration remain unchanged. String options become `{value, label}` in response copies.

## Comments

`comment.locale: 'auto'` follows the system language (`en-US` maps to Waline `en`). Explicit legacy values retain precedence. Existing CAPTCHA language choices are unchanged.

## Delivery status

The core admin routes and shared controls support Chinese and English, including CAPTCHA schema labels and the Ant Design X chat locale. Language changes preserve unsaved form input. Stored values such as comment reply tones and translation target languages remain unchanged; only their labels are translated.

User-authored posts, comments, category names, and other stored content remain in their original language. Third-party plugin/theme text still requires dictionaries from its owner, and unknown external errors retain their original message. Default-theme text coverage and deployment/cache acceptance remain separate work; the release-check draft (#983) was closed without merging.
