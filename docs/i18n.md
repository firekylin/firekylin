# UI internationalization

The site-wide `locale` setting defaults to `zh-CN` and supports `en-US`. It changes UI text only; article bodies, titles, categories, navigation values and custom field values are not translated. React text migration is incremental.

## Translators

`t(key, vars)` returns plain text synchronously. Keys match exactly, including dots, colons and whitespace. Flat JSON dictionaries live in `locales/<locale>.json` inside the owning core, theme or plugin root. Only `{{name}}` placeholders are supported. Values are primitive strings, numbers, booleans or nullish values. Interpolation runs once; use the final consumer's escaping (React text or Eta `<%=`).

Fallback stays within the owner: exact locale, base language, default locale, original key. Empty translations are valid. Resources reject duplicate keys, inconsistent placeholders, prototype keys, oversized files and escaping symlinks.

## Plugins

Use `ctx.t('保存')` in registration or callbacks. Each plugin retains its own dictionary even when invoked by another plugin or a theme. HTTP callbacks inherit the request's immutable locale snapshot. For an independently scheduled task, explicitly call `ctx.withLocale(async () => { /* task */ })` at task entry to read the current persisted locale.

Strings evaluated during `register(ctx)` remain in that language until a safe plugin reload or worker restart. Changing locale does not rerun registration, restart workers or duplicate external side effects. Dynamic callbacks should call `ctx.t` when invoked rather than cache translated strings.

## Themes

Use `<%= firekylin.t('阅读全文') %>` for escaped text. A fixed Eta header also provides `t()` when no existing `t` identifier is detected in theme code; legacy themes with conflicts keep their original scope. Includes must preserve `firekylin.t` when passing explicit replacement data. Do not use raw output for translations.

The host translates only known display properties in `configElements` and `themeFields`. Names, defaults, submitted values and stored user configuration remain unchanged. String options become `{value, label}` in response copies.

## Comments

`comment.locale: 'auto'` follows the system language (`en-US` maps to Waline `en`). Explicit legacy values retain precedence. Existing CAPTCHA language choices are unchanged.
